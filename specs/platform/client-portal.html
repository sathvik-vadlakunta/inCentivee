SPEC · PLATFORM

Client Portal

A persistent, login-gated place for a client to check their own PracticeRank stats whenever they want — no expiring links, no admin-panel access. Built entirely on data and rendering we already have: compute_practicerank_score(), weekly_report.build_report_data(), and the existing report_snapshots table. This file is both the spec and a rendered mockup of all four pages (scroll down).

Owner: Kody · Status: Draft v1 · Lives in specs/platform/ · Precedent: weekly-customer-report.html

1. Goal & principles

  • The customer is a dental practice owner, not a marketer. No SEO/AEO jargon — every metric gets a plain-English explanation of what it means and why it matters to their practice.
  • Score first, breakdown second. The PracticeRank Score is the single number a client tracks over time — it's the headline. Immediately below it, "what makes up your score" explains the 5 weighted pillars in plain language, since the score means nothing without knowing what drives it.
  • Every category is a door, not a dead end. Each pillar bar on the Overview is a link into a dedicated detail page for that category, showing the actual underlying metrics (e.g. AI Visibility → your hit rate on each individual AI assistant, not just one blended percentage). A summary number is not "clear" on its own — clarity means being able to see what's behind it.
  • Real accounts, not links. Unlike the existing /r/<token> share-link report (still used for ad hoc sharing), the portal uses real email/password login so a client has one stable place to return to, and staff can revoke access per person.
  • Zero admin surface. Client sessions use entirely separate session keys from staff logins and a separate page shell — there is no path by which admin navigation, other customers' data, or internal operational detail (competitor DA gaps, off-site vendor line items, system alerts) reaches this experience.
  • Reuse, don't recompute. Every figure on these pages already exists in the DB or is already computed by weekly_report.py. This spec adds no new metrics — only a client-appropriate presentation layer.
