FATJOE — VA Operations & Results Tracking

The operational layer on top of the pricing spec: exactly how a VA places, QAs, and records FATJOE orders; how we ingest FATJOE's unbranded reports; and how we track the authority lift back to DA, referring domains, rankings, and AI citations so we can prove ROI in the weekly report.

Owner: Kody · Vendor: FATJOE (white-label reseller) · companion to link-building-pricing.html, local-relevancy-engine.html, lever-b-citations-nap.html · 2026-06-18

Scope & goal

The pricing spec decided what we buy and bundle. This spec decides who does it, how, and how we measure it. Three outcomes:

  • A repeatable VA playbook — a VA with no SEO background can place every FATJOE order correctly (right target URL, right anchor, right DR tier, right cadence) from the Local SEO tab.
  • A results ledger in the app — every order is a tracked row from ordered → delivered → live → indexed, with cost, the live URL, and that URL's DA.
  • Report ingestion + ROI proof — FATJOE's CSV report uploads into the customer record, auto-pulls each live link's DA via Moz, and feeds the weekly report's authority section (which already shows the DA week/month/started deltas).
Client-facing rule: the client only ever sees PracticeRank. FATJOE reports are unbranded; we never forward their CSV — we ingest it and re-present it as our own "Authority work this period."

Part 1 — VA Playbook (full instructions)

citations  A · Local citation order (onboarding + top-ups)

Open the customer's Local SEO tab. Confirm the canonical NAP block at the top is correct and complete (name, address, phone, website). Everything downstream copies this — fix it first if wrong.
In the FATJOE reseller dashboard, choose Local Citations → package size per the client tier (new local = 100; competitive top-up = 50).
Fill the order form with the canonical NAP character-for-character: business name, full address incl. suite, phone in one consistent format, website URL, primary category, 2–3 service keywords, business hours, a 1–2 sentence description, and (if asked) a logo + one photo URL.
Set turnaround to standard (~7 days). In order notes: "Match NAP exactly as provided — do not reformat phone or abbreviate street."
Submit, then in the app open Off-site → New order, log it as type citation, qty, cost, status ordered. (Or click "Order citations" on the citation step once ordering is wired — Phase 3.)
On delivery: FATJOE returns a CSV of submitted directories + screenshots. Upload it via Off-site → Import report (Part 3). Spot-check 5 random listings live for NAP accuracy before marking delivered.
Citations are NAP submissions, not editorial links — there's no anchor text. The only thing that matters is exact, consistent NAP. One wrong suite number across 100 dirs actively hurts ranking.

link  B · Blogger outreach link (monthly drip)

Confirm the client is due a link this month per their tier (the Off-site panel shows "links this month: 1 of 2"). Don't over-order — natural velocity beats volume.
Pick the target URL. Rotate across the pages that need authority, not always the homepage:
  • Money pages: a core service page or a top city/service page (e.g. /sell-gold-springfield).
  • ~40% homepage, ~60% deep pages over time — see anchor/target strategy below.
Choose the DR tier from the tier table — new local = DR20–30. Don't buy DR50+ for a low-authority local site; it looks engineered and wastes margin.
Set the anchor text per the ratio rules (next card). When unsure, use a branded or URL anchor — never an exact-match commercial anchor two months running.
Niche/topic: pick the closest niche to the client's vertical (dental → health; law → legal/finance; gold buyer → finance/lifestyle). In notes: "US-based site preferred; topic relevant to {city} {service}."
Let FATJOE write the content (included). Submit. Log in the app as type link, with target URL, anchor, DR tier, cost, status ordered.
On delivery (~14 days) QA the live URL (next-but-one card), then import the link report. The app pulls the live page's DA via Moz and stores it on the link row.

Anchor text & target-URL rules (the part VAs get wrong)

Spammy anchors are the fastest way to make cheap links backfire. Hand the VA this fixed distribution — aim for roughly, over each client's running link history:

Anchor typeShareExample for a Springfield gold buyer
Branded~40%"Springfield Gold & Coin", "Springfield Gold"
Naked URL~20%springfieldgold.com
Generic / natural~20%"this local gold buyer", "read more", "here"
Partial-match~15%"sell gold in Springfield", "Springfield coin shop"
Exact-match commercial≤5%"sell gold Springfield" (use sparingly, never repeat)
  • Never the same exact-match anchor twice for one client.
  • Match the anchor to the target page (city/service anchor → that city/service page, not the homepage).
  • The app should warn when a new order's anchor type would push the client's exact-match share over 10% (Phase 2 nicety).

mention  C · Brand mention (quarterly / AI-visibility add-on)

Order ~quarterly for base clients, or on demand when selling the "AI Visibility pack" add-on.
In FATJOE choose Brand Mentions, DR30–60 range. Provide: business name, city, website, the 1–2 facts you want surfaced (e.g. "family-owned since 2004", "same-day gold appraisals"), and the vertical.
Notes: "Positive, natural mention in a listicle/roundup; include city; aimed at AI/LLM visibility." Mixed follow/nofollow is fine — the goal is a citable mention, not link juice.
Log as type mention. On delivery, import the report; the live URL becomes a candidate "source now citing you" once it shows up in grounded AI answers.

Deliverable QA checklist (every link before it's marked live)

  • ✅ Link is live and loads (not 404 / not "coming soon").
  • ✅ Link is do-follow for blogger-outreach orders (check page source for rel="nofollow" — citations/mentions may be nofollow, that's fine).
  • ✅ Points to the exact target URL we ordered, with the exact anchor.
  • ✅ Surrounding content is on-topic and reads like a real post (not a thin link farm; no obvious PBN footprint).
  • ✅ Page is indexable (no noindex) — paste the URL into Google in ~2 weeks to confirm it's indexed.
  • ✅ The live page's DA (pulled by the app via Moz) is within ~5 of the tier we paid for. If a DR30 order lands on a DA8 page, raise a redo with FATJOE (lifetime guarantee covers it).
If any check fails, do not mark it live — set status redo_requested and file the guarantee claim with FATJOE. Track the redo on the same order row.

Part 2 — Tracking results (data model)

New table: offsite_orders

One row per FATJOE order. Lives in geo_agent/db.py alongside citations / kpis.

offsite_orders
  id              INTEGER PK
  customer_id     TEXT  FK
  vendor          TEXT  DEFAULT 'fatjoe'
  order_type      TEXT  -- citation | link | mention
  status          TEXT  -- ordered | in_progress | delivered | live | indexed | redo_requested | cancelled
  quantity        INTEGER       -- citations: pack size; links: 1
  dr_tier         INTEGER       -- links only (20/30/40…)
  target_url      TEXT          -- page we pointed the link at
  anchor_text     TEXT
  anchor_type     TEXT          -- branded | url | generic | partial | exact
  cost_usd        REAL          -- our wholesale cost
  vendor_order_id TEXT          -- FATJOE order ref
  ordered_at      TEXT
  delivered_at    TEXT
  notes           TEXT

New table: offsite_assets (delivered live URLs)

A citation order yields ~100 assets; a link order yields 1. This is what powers the live-links table and the report.

offsite_assets
  id            INTEGER PK
  order_id      INTEGER FK -> offsite_orders
  customer_id   TEXT FK
  asset_type    TEXT   -- citation | link | mention
  live_url      TEXT
  domain        TEXT
  anchor_text   TEXT
  is_dofollow   INTEGER
  da            INTEGER       -- pulled via moz_client.get_domain_authority(domain)
  da_checked_at TEXT
  indexed       INTEGER       -- verified in Google
  live_at       TEXT
DA per asset reuses the existing geo_agent/moz_client.py. Batch the lookups (one Moz call per unique domain) to stay inside the API plan — cache by domain across customers.

Part 3 — Ingesting FATJOE's reports

Import flow

VA downloads the unbranded CSV from the FATJOE order (links report or citation report).
In the app: Local SEO tab → Off-site panel → Import report, picks the matching open order, drops the CSV.
Parser (geo_agent/fatjoe_import.py) maps FATJOE's columns → offsite_assets. Column maps are stored per report type because FATJOE's headers differ between citations and links.
For each asset: normalize the domain, dedupe against existing assets for that customer, and queue a Moz DA lookup (batched by domain).
Order auto-advances ordered → delivered; assets land as live; the VA QAs and flips verified ones to indexed later.
# geo_agent/fatjoe_import.py  (sketch)
COLUMN_MAPS = {
  "link":     {"Live URL": "live_url", "Anchor": "anchor_text", "DR": "_dr"},
  "citation": {"Directory URL": "live_url", "Directory": "domain"},
  "mention":  {"Published URL": "live_url", "Anchor": "anchor_text"},
}
def import_report(db, order_id, csv_bytes):
    order = db.get_offsite_order(order_id)
    rows = parse_csv(csv_bytes, COLUMN_MAPS[order["order_type"]])
    for r in dedupe(rows, db, order["customer_id"]):
        r["da"] = moz_da_cached(domain_of(r["live_url"]))
        db.add_offsite_asset(order_id, order["customer_id"], **r)
    db.update_offsite_order(order_id, status="delivered",
                            delivered_at=now_iso())
Keep the raw CSV in data/offsite_reports/{customer}/{order_id}.csv for audit, but never expose it client-side. We re-present the data, not the vendor's file.

Dashboard UI — "Off-site / Authority" panel (Local SEO tab)

  • Order queue: open orders with status chips (ordered / in progress / delivered), "Import report" + "Mark live" actions.
  • Live links table: live_url · anchor · DA · do-follow? · indexed? · date — sortable by DA.
