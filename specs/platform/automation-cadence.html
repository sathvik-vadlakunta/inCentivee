Automation Cadence

What runs automatically, and when — so the platform produces results without anyone clicking buttons. Every manual "Generate" action has a scheduled equivalent. The principle: bootstrap a new company immediately on add, then keep each signal fresh on the cheapest cadence that still feels live.

Content generation (the AI "Generate New" crawl) stays on-demand + monthly via the local-relevancy run; the bi-weekly search-data engine is the steady driver because it's grounded in real demand, not a crawl.

What changed in this pass

  • DA now refreshes weekly (added to weekly_reports.py) instead of only monthly — so the report's "▲ +N vs last week" DA pills and the over-time chart fill in properly.
  • Search-data content (#5) is now scheduled bi-weekly (biweekly_content.py) — previously it only ran when someone clicked "From Search Data".
  • On-add bootstrap is heavier — beyond services + cities, it now sets a DA baseline and runs a first local-relevancy pass, so a new company is "going" immediately (the user's ask).

Crontab (droplet)

Add to the practicerank user crontab (crontab -e). The dashboard container has the code + env; everything execs into it.

# Daily
0 6 * * *      docker exec practicerank-dashboard python3 /app/scripts/daily_gsc_pull.py     >> /app/data/logs/gsc.log 2>&1
30 6 * * *     docker exec practicerank-dashboard python3 /app/scripts/daily_score.py         >> /app/data/logs/score.log 2>&1

# AI mentions — Mon/Wed/Fri
0 10 * * 1,3,5 docker exec practicerank-dashboard python3 /app/scripts/scheduled_ai_check.py --all >> /app/data/logs/ai-check.log 2>&1

# Weekly — Monday (report + conversions + DA)
0 8 * * 1      docker exec practicerank-dashboard python3 /app/scripts/weekly_reports.py      >> /app/data/logs/weekly.log 2>&1

# Bi-weekly content — every other Monday 07:00 (even ISO weeks)
0 7 * * 1      [ $(( ($(date +\%s) / 604800) \% 2 )) -eq 0 ] && docker exec practicerank-dashboard python3 /app/scripts/biweekly_content.py --all >> /app/data/logs/biweekly-content.log 2>&1

# Monthly — 15th (local relevancy + KPIs)
0 6 15 * *     docker exec practicerank-dashboard python3 /app/scripts/monthly_local_relevancy.py --all >> /app/data/logs/local-relevancy.log 2>&1
0 7 15 * *     /home/practicerank/dental-marketing/scripts/track-kpis.sh

Verify which of these are already installed with crontab -l before adding — daily GSC, 3×/week AI, and weekly reports likely already exist; the new lines are bi-weekly content and the DA addition (which rides inside the existing weekly job, no new cron needed).

Manual override still available

Every scheduled action keeps its dashboard button for on-demand runs (new customer you want to push, a client asking for fresh ideas, debugging): "Generate New" / "From Search Data" on Content, "Refresh" on Domain Authority, the local-relevancy run, and the AI-mention check. Automation is the floor, not a cage.
