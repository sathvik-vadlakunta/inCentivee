From activity to outcomes

Six builds that move the story clients renew for — new patients, a defensible AI-search moat, and results they feel in the first month. Most of this is wiring on systems we already have, not greenfield.

The through-line

Retention is the whole business.

At ~$3,000/mo, one saved cancellation is worth more than a new logo. Every item here serves retention through one of three moves: prove the outcome (01), own a category nobody else can claim (02–03), and make results happen fast and visibly (04–06). We already collect most of the data — the work is turning it into a number a dentist repeats to their spouse.

01

Make patient outcomes the headline, not activity

Churn-criticalLow effortWire existing

A dentist doesn’t renew for “12 blog posts and 4 backlinks.” They renew for “you got me 14 new patients.” Today the report leads with effort; it should lead with inquiries and estimated production.

Already in place
  • lead_tracking.py ships a paste-once snippet that fires phone_click / form_submit / appointment_request to GA4 or GTM.
  • ga4_client.track_conversions() pulls those into the conversions_daily table; weekly_report.build_report_data() already renders a leads section with period-over-period deltas.
The fix
Data
  • Add avg_case_value (cents) to customers — Dan sets it once per client.
  • Optional close_rate (default an industry ~0.35) to translate inquiries → booked patients.
Backend
  • outcomes.py: inquiries = calls + forms + booking clicks over the period; est. production = inquiries × close_rate × avg_case_value.
  • Roll a rolling series into the report payload for a trend.
Report
  • New hero band above the fold: “14 new patient inquiries · ~$38k in potential production.”
  • Feed the headline number into _exec_summary() so the summary line leads with it.
Operator (Dan)
  • One field on the customer page: “Average case value.” Tooltip explains it drives the ROI headline.
  • Dashboard: a patients-attributed sparkline beside the SEO-score column already added to index.html.
Honesty guardrail: label it “potential/attributed production,” never “revenue we generated.” Attribution is directional (organic-channel conversions), and overclaiming is the fastest way to lose a smart client. The number persuades because it’s grounded, not inflated.
Done when
The monthly report’s first line is a patient/production number, Dan can set avg case value in the UI, and the dashboard shows a per-client attributed-patients trend.
02

The AI Share-of-Voice score — our moat metric

Category of oneDifferentiatorMedium effort

Every agency does backlinks and blogs. Almost none can say “we get you recommended by ChatGPT, Perplexity, and Google AI Overviews.” We already check AI mentions — productizing it into a tracked, competitive Share-of-Voice score is what justifies $3k and what nobody else can credibly sell.

Already in place
  • ai_mention_runs / ai_mention_results tables + the weekly AI-mention check already record whether a practice is named by AI engines.
  • The weekly report has an ai section with a mention rate and trend.
The fix
Data
  • A curated set of commercial queries per client (“dental implants {city}”, “emergency dentist near me”, “Invisalign cost {city}”).
  • ai_sov_daily: per query × engine × date → named? position? competitors named alongside?
Backend
  • Run each query across ChatGPT / Claude / Perplexity / Google AIO; parse whether the client and each competitor are cited.
  • SoV = client mentions ÷ total brand mentions across the query set, weighted by query value. One 0–100 flagship number + trend.
Report + sales
  • A dedicated report module: “AI Share-of-Voice: 34% → 51%, now ahead of {competitor} in 6 of 10 buyer questions.”
  • Same widget powers the sales demo — a live “watch us get you named” proof.
Operator (Dan)
  • Approve the per-client query set once at onboarding (seeded from tracked keywords + services).
  • Dashboard tile: SoV score + arrow, sortable, beside the SEO score.
Cost control: query panels are the spend here. Cap at ~10 queries × the engines, run weekly not daily, cache aggressively — this rides the same budget discipline as the rest of geo_agent. Emphasize movement (trend) over absolute counts so a slow month still tells a story.
Done when
Every client has a weekly 0–100 AI Share-of-Voice score with a competitor comparison, surfaced in the report and on the dashboard, and it’s the lead metric in the sales deck.
03

Weight content to money queries, not traffic

ContentHigh impactLow effort

Informational traffic (“what is a cavity”) looks great in a report and books nobody. Commercial-intent queries (“implants cost”, “emergency dentist near me”, “financing”) fill chairs. The intent engine already exists — this is about enforcing it and showing it.

Already in place
  • keyword_intent.classify_intent() returns transactional / commercial / informational, with weights 2.0 / 1.5 / 0.4 and a rank in intent_rank().
  • INTENT_META already carries UI labels + colors (“Buy/Action”, “Compare/Decide”, “Research”).
The fix
Backend
  • Make intent_rank an explicit sort/gate in content_recommender.py: transactional & commercial topics get generated first; informational only fills a small “top-of-funnel” quota.
  • Store the intent tier on each content_recommendations row so it’s reportable.
Report + UI
  • An intent-mix bar in the report and content queue: “this month — 70% buyer-intent, 30% research.”
  • Color the queue chips by INTENT_META so Dan sees at a glance he’s shipping money content.
Done when
Content generation is intent-ordered (commercial-first with an informational cap), each rec shows its intent tier, and the report displays the buyer-vs-research mix.
04

Automated review engine — white-label, don’t build

Highest local ROIIntegrate a vendorLow–Med effort

Service businesses stall on reviews, and review velocity is the strongest local-pack lever there is. Per your call: integrate/white-label a proven service, don’t build a CRM. Good news — Grade.us is already in the target stack for exactly this.

Recommendation

Grade.us (Agency, white-label) as the sending/funnel engine — it’s already in our stack, brandable as PracticeRank, and cheapest per location. We build only a thin layer: get contacts in and pull velocity back out.

Getting contacts in — “connect to theirs,” tiered
Tier 1 — zero build
  • CSV upload / paste list into Grade.us — works for every client on day one.
  • Zapier bridge from their booking/PMS (Jane App, Dentrix, Open Dental, Weave) → Grade.us campaign.
Tier 2 — thin build later
  • A “completed visit” webhook endpoint that forwards to the vendor — for practices whose PMS can post out.
  • Reuse our Resend sender only as a fallback if a client can’t use the vendor.
What we build (thin orchestration + tracking)
Backend
  • Nightly pull of new-review counts (vendor API, or the Google/BrightLocal data we already gather) into reviews — we already have add_review, get_review_stats, get_competitor_review_gap.
  • Velocity = reviews/month; per-client target; a stall alert when velocity drops (via the same action_items + alerts path).
Report + operator
  • Report line: “+6 reviews this month (4.9★) — now within 12 of {competitor}” using the existing review-gap function.
  • Onboarding step: “Connect review requests” (upload list / connect Zapier). Dashboard velocity tile + stall alert for Dan.
Compliance — do not gate reviews. Google prohibits “review gating” (soliciting only happy customers for public reviews). Configure the funnel to ask every patient for a public review and additionally offer a private feedback path — not one-or-the-other by sentiment. Grade.us supports a compliant flow; keep it that way.
Done when
A client’s patient list feeds a white-labeled Grade.us campaign in <15 min of onboarding, new reviews flow back into our reviews data, and Dan sees a velocity target + stall alert per client.
05

Kill early churn with a Day-1 quick win

Early-churnLow effortStandardize existing

Deals die in weeks 1–4 when a client sees nothing happen. A guaranteed, visible first result buys the trust that carries the relationship.

Already in place
  • quick_wins.detect_quick_wins() + prioritize() already find fast, high-value fixes across AI visibility, search health, technical, content, and reputation.
  • status_checker reconciliation already resolves fixed audit issues and ticks onboarding todos.
The fix
Standard Day-1 pass
  • A fixed checklist: LocalBusiness/Dentist schema live, GBP category + hours + photos corrected, and the worst 3 audit issues fixed.
  • Gate the onboarding checklist on “quick win shipped” — onboarding isn’t “done” until a visible fix is live.
Prove it
  • Capture a baseline at onboarding, then surface a “first result” in the first report — a keyword newly ranked, GBP impressions up, schema now valid.
  • Trigger the first report a bit earlier (2–3 weeks) specifically to show the quick win.
Done when
Every new client gets a standardized Day-1 pass, onboarding can’t complete without a shipped quick win, and the first report shows a concrete “first result” against baseline.
06

Churn-risk radar on the dashboard

RetentionMedium effortNew score

The accounts that cancel are usually the quiet ones — no fireworks, results drifting sideways, no recent touchpoint. Dan should be able to sort by who’s about to leave, not just who has an active alert.

Already in place
  • action_items.customer_action_items() + worst_severity() already compute per-client attention signals.
  • db.seo_score_and_delta() (added this cycle) gives a results-trend; the health-tracking pattern from the System Health page is reusable.
The fix — a 0–100 renewal-risk score
Signals (weighted)
  • Results trend — SEO/PracticeRank score delta & SoV movement (flat/negative = risk).
  • Review velocity — stalled reviews (from 04).
  • Engagement — content approvals, logins, responses to “what we need from you.”
  • Touchpoint recency — days since last report opened / last contact.
Surface
  • churn_risk.py computes the score nightly; store history like seo_health_history.
  • Dashboard: sort by renewal risk; a red/amber “at-risk” band with the top reason (“results flat 60d + no login 21d”).
  • Feed high-risk accounts into the daily attention digest so Dan intervenes before the cancel email.
Done when
Every active client has a nightly renewal-risk score with a plain-language top reason, the dashboard sorts by it, and at-risk accounts surface in Dan’s daily digest.
Recommended build order

Sequence by value-per-effort

Two levers first because they hit retention and price hardest for the least work; the review engine in parallel since it’s mostly vendor config; the rest as fast follows.

Phase 1 · now

01 Outcome-led reporting  ·  04 Review engine (vendor config)

Both are low-build, high-retention. 01 is wiring data we already collect; 04 is Grade.us setup + a CSV/Zapier intake and a velocity pull. Fastest felt impact for clients.

Phase 1 · now

03 Money-query weighting

A small change to content_recommender ordering + an intent-mix chip. Compounds the value of everything we publish.

Phase 2 · next

02 AI Share-of-Voice score

The moat and the sales weapon. Medium build (query panels + parsing), so it follows the quick wins — but it’s the one that defends the $3k.

Phase 2 · next

05 Day-1 quick-win pass

Standardize quick_wins into a gated onboarding step; pairs naturally with 01’s baseline capture.

Phase 3 · then

06 Churn-risk radar

Best built last — it consumes signals from 01, 02, and 04, so it’s most accurate once those exist.
