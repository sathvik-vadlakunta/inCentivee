Weekly Customer Progress Report

How PracticeRank produces and delivers a weekly client-facing report that shows SEO progress, keyword movement, visitor counts, AI search visibility, and wins — built entirely on data we already collect. This file is both the spec and a rendered mockup of the deliverable (scroll down).

Owner: Kody · Status: Draft v1 · Last updated 2026-06-17 · Lives in specs/platform/

1. Goal & principles

Give every customer a recurring, branded touchpoint that proves we're moving the needle — without drowning them in metrics. Research is consistent on what makes client SEO reports work, and we follow it:

  • Lead with the "wow," then the proof. Open with a plain-English executive summary (the trailer), then the supporting KPIs, then the behind-the-scenes work. Founders care about progress toward goals, not raw numbers.
  • Explain why numbers moved. Never just restate metrics — tie each change to a specific action we took or an external cause.
  • Avoid information overload. The #1 reporting mistake is too many metrics. Core report stays scannable in <2 minutes; deep data is linked, not inlined.
  • Show trend, not just snapshot. Week-over-week deltas plus a rolling trend tell a far more convincing story than a single number.
  • Always close with next steps. What we did, what's coming, and any decision we need from them.
  • One composite score for at-a-glance progress. Our PracticeRank Score (0–100) is our "search visibility score" — the single number a client tracks over time.

Sources: TapClicks · Reportr (weekly) · EarlySEO · Nightwatch · SEO Sherpa · AgencyAnalytics (Local SEO)

Cadence reality check. SEO data moves slowly — most agencies report monthly with a live dashboard, because week-over-week organic numbers are noisy. Recommendation: send the weekly report, but frame it as "activity + early signal," and keep the heavyweight analysis (rankings story, competitor gap, ROI) in the monthly report (04-monthly-report.md). Smooth noisy metrics (AI mention rate) with a rolling 4-week average, which the scoring already does.

2. Report structure

Ten sections, in narrative order. Sections 6 (Leads) and 8 (Local listings) depend on the R3/R4 integrations below and render only when connected.

1Executive summary2–3 sentences in plain English: the week's single biggest win + headline number. AI-generated from the deltas.
2PracticeRank Score0–100 composite + grade, with week-over-week change and the 5 pillar sub-scores as bars. The "track this over time" number.
3Search performanceClicks, impressions, avg position, CTR — this week vs last (GSC). The visitor-count story.
4KeywordsTop performing keywords table + movers (up/down by position). Where the traffic comes from.
5AI search visibilityOur differentiator. Mention rate %, avg position in AI answers, per-engine breadth (ChatGPT/Claude/Perplexity/Google AIO/Bing). + llms.txt bot hits.

7Reviews & reputationGoogle rating + review count, week's new reviews, sentiment, gap vs nearest competitor + gap trend (R2).
8Local listings health R4NAP consistency score + directories with issues (BrightLocal). Hidden until connected.
9What we did (wins)Published content, schema/llms.txt changes, resolved technical issues, alerts handled. Pulled from run history + content_recommendations.
10What's nextPlanned actions + any decision/asset we need from the client.

4. Generation & delivery

Pipeline

  • A weekly job (Hangfire/cron on the droplet) iterates active customers (onboarding_step IN live/content/monitoring).
  • Pull this-week vs prior-week windows from the DB; compute deltas + score.
  • Claude writes the executive summary + "why it moved" lines from the deltas (brand voice per customer).
  • Render the HTML (this template) → store snapshot → email + dashboard download.

Delivery

  • Email: inlined-CSS HTML, same content as below. Existing markdown lives in templates/emails/07-weekly-seo-update.md — this HTML supersedes it as the rendered version.
  • Dashboard: new route /report/<customer_id>/weekly serving the latest snapshot + history.
  • Schedule: same weekday/time each week (e.g. Monday 8am local) for consistency.

Template variables

Reuses the existing placeholder names from 07-weekly-seo-update.md: {practice_name} {report_week} {weekly_clicks} {weekly_clicks_delta} {weekly_impressions} {weekly_avg_position} {weekly_ctr} {top_keywords_table} {keyword_movers} {ai_mentions} {ai_visibility_rate} {practicerank_score} {practicerank_grade} {practicerank_delta} {quick_wins_summary} {weekly_activity_summary} {weekly_next_steps} plus new: {exec_summary} {pillar_*} {rating} {review_count} {new_reviews} {llms_hits} {engine_chips}.
