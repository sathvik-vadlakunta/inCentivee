Industry-Aware SEO/GEO Checklist

Replace the binary practice/non-practice task split with industry verticals, make the schema & content tasks fit each customer's actual business, and tie content tasks to the content we really generate so the checklist reflects reality.

Owner: Kody · Status: Spec (approved to build) · 2026-06-17 · specs/active/checklist-overhaul.html

1. Problem

The task list (SEO_GEO_TASKS in dashboard/app.py) is filtered by a single boolean:

# today — only two buckets, and legal is wrongly lumped with practice
is_practice = business_type in ("practice", "legal", "medical")
if t.get("practice_only") and not is_practice: skip
if t.get("non_practice_only") and is_practice: skip

Consequences on the live book (actual business_type counts):

business_typecountgets…problem

legal2Dentist + MedicalProcedure tasks✗ law firms aren't dentists
precious_metals_buyer1SoftwareApplication, Product, "use-case pages per product", "alternatives pages"✗ Paradigm — a metals buyer, not SaaS
ecommerce / product2SaaS tasks✗ partly — needs Product/Offer, not SoftwareApplication
technology1SaaS tasks✓ mostly fine

Plus the content tasks use SaaS language ("for each product", "alternatives pages") for everyone non-practice, and none of the content tasks are tied to the content we actually generate — so they sit at 0/N even after we've shipped the work.

Introduce a small set of verticals; map each business_type to one. Unknown types fall back to default (generic local business). This is a pure code map — no DB migration.

BUSINESS_TYPE_VERTICAL = {
  "practice":"practice","medical":"practice","dental":"practice",
  "legal":"legal",
  "precious_metals_buyer":"local_retail","retail":"local_retail","shop":"local_retail","jeweler":"local_retail",
  "ecommerce":"ecommerce","product":"ecommerce",
  "consulting":"professional_services","advisory":"professional_services","agency":"professional_services","finance":"professional_services",
  "technology":"saas","saas":"saas","software":"saas",
}
def vertical_for(bt): return BUSINESS_TYPE_VERTICAL.get((bt or "").lower(), "default")

5. Code changes

Task definitions

  • Each SEO_GEO_TASKS entry: replace practice_only/non_practice_only with "verticals": [...] (or omit = all).
  • Per-vertical label override via "labels": {"legal": "…", "local_retail": "…"} so one key can read correctly per industry (e.g. LocalBusiness vs Store vs Dentist).
  • Add the new keys: seo_schema_legalservice/software/person/service, seo_blog_cadence, seo_fresh_content, and vertical content tasks.

Filtering & detection

  • _get_seo_tasks: resolve vertical_for(business_type), filter by verticals, apply the per-vertical label.
  • _auto_detect_seo_status & status_checker.detect_live_status: add the JSON-LD patterns in §3; add content-rec auto-tick (query published recs by rec_type).
  • Keep platform_only / skip_platforms untouched.
