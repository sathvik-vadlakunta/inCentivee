P1 — Fix now (the gaps that cost rankings + leads)

1 · Areas We Serve / location pages (the one you flagged)

Oak Ridge generates a dedicated, locally-written /dentist/{city} page for each nearby city via dentist/[location].astro, driven by a areaServed array in practice.json, surfaced in the Nav as an "Areas We Serve" dropdown. Sojo has none of this — so it can't rank for "dentist in {nearby city}" / "near me" and gives AI no service-area signal.

Fix: add areaServed to Sojo's practice.json (South Jordan + West Jordan, Riverton, Herriman, Bluffdale, Draper, Sandy, Salt Lake County), port dentist/[location].astro + Testimonials.astro from Oak Ridge, and add the Nav dropdown. Each page gets a custom lede, the service grid, a directions map, testimonials, and LocalBusiness/areaServed schema.

2 · Analytics + lead tracking

Sojo's practice.json has no analytics block — so there's no GTM/GA4 wiring and, critically, no form_submit / click_to_call events. That's the exact "we can't see leads" gap from the platform side. Add the analytics config (GTM container or GA4 ID) and ensure the contact form + every tel: link fire events. (This pairs with the dashboard lead-tracking snippet — the site should fire the same phone_click / form_submit events GA4 ingests.)

3 · 404 page

No 404.astro → unknown URLs soft-404 to the homepage, which Google dislikes and which breaks the "every old URL 301s, unknown → 404" rule. Port Oak Ridge's 404.astro (one file).

P2 — Strengthen

  • Homepage testimonials: port the reusable Testimonials.astro (real 4.6★/143 Google reviews) so social proof is on the homepage and location pages, not just the reviews page.
  • FAQ / AEO depth: Sojo has roughly half the FAQ coverage of Oak Ridge. Add 4–5 FAQPage-schema FAQs to each service page and the new location pages — this is the content AI assistants quote, and it ties straight into the dashboard's search-data content engine.
  • Maps directions: add mapsApiKey so location pages show a real per-city driving-directions embed instead of the static fallback.

P3 — Needs client data

  • Financing widget (cherryUrl), online-booking/chat (deardocSrc), pay-online (payNowUrl), full insuranceList — Oak Ridge has these; Sojo doesn't. They lift conversion but need the client's actual URLs/accounts, so they're a follow-up once we collect them.

What's already good (don't touch)

  • Real services (24), real provider bios as crawlable /team/<slug> pages (Dr. Call, Dr. Ogden), real NAP + geo.
  • Dentist + AggregateRating + Speakable schema, llms.txt / llms-full.txt, robots.
  • 7 real blog posts (more than Oak Ridge's 4), South-Jordan-localized.
  • Real 4.6★ / 143 Google rating wired with the correct Place ID.

Bottom line: Sojo's foundation is solid; it's missing the local-reach layer (Areas We Serve), the measurement layer (analytics/lead events), and the 404. Those three are the P1 fixes — the first is the headline.
